# 鹰角两款游戏 PC 端 token 获取方式调研（2026-10-18）

> 纯调研，为给 ArkRecord 桌面版选型。没有登录任何账号，没有用任何真实凭据。
> 证据等级标注：**实测**＝本环境不带凭据请求公开页面/读官方前端 JS；**源码确认**＝读了开源项目源码；
> **转述**＝只看到搜索摘要，原文被代理拦截/DNS 失败；**推测**＝无直接证据。

## 0. ArkRecord 现有接口链（worker/upstreams.ts、docs/rewrite/research.md）
账号 token（account/info/hg 的 data.content）→ as grant（appCode be36d44aa36bfb5b,type1）→ OAuth
→ binding_list（appCode=arknights/endfield）→ u8_token_by_uid → u8 token
→ 明方：ak role/login 拿 Cookie ak-user-center 再查 inquiry/gacha/*；终末地：ef-webview/api/record/* 直接带 u8。
下文“拿 token”均指链首账号 token。

## 1. 终末地 PC 客户端 / 鹰角启动器
- 鹰角启动器统一分发；终末地 2026-01-22 公测即用，明方 PC 端 2026-02-10 起也用（确认，ak.hypergryph.com/news/0717）。官方渠道版与 bilibili 渠道版互不兼容（确认）。启动器技术栈、本地登录态存储位置：未知。
- 本地日志目录（官方 FAQ，转述）：国服 `%USERPROFILE%\AppData\LocalLow\Hypergryph\Endfield\sdklogs\HGWebview.log`，国际服 `…\LocalLow\Gryphline\Endfield\sdklogs\HGWebview.log`。
- 游戏内“寻访记录”是 WebView（确认）。加载 `https://ef-webview.hypergryph.com/page/gacha_char?u8_token=<u8>&server=<id>&…`（国际服 ef-webview.gryphline.com）。1.1 前日志里有 `WebPortal url: <该URL>`。
- 该页面只从 URL 参数读 token（依次 u8_token/token），JS 里唯一一处 localStorage 存的是调试浮层状态，不存 token（实测，读 commons.0174ee.js）。→ Local Storage 一般找不到 token；token 只在 URL，理论上可能残留在 WebView 缓存/历史（推测，无人实现）。WebView 内核（WebView2/CEF）未知。

### 1.1 关键变化：1.1 版本（2026-03-12）起日志不再写该链接（多来源一致）
- RisingSunLight42 README：「Since 1.1, the extractor can no longer work since the url generated by the application isn't logged anymore」（源码确认；提交 af04550「add: informations about 1.1」2026-03-29）。
- RoLingG/EndField_Gacha_App README：原 HGWebview.log 在线同步「因官方调整日志显示规范已永久移除」，改用内置登录窗口（源码确认；提交 b32195b「日志模式退役全链路移除」2026-09-12）。
- xqf946/gacha-query endfield.py：读日志保留但注明「官方可能已调整日志写法，有的机器已不认日志里的令牌」。
- 巴哈/17173 转述：约 2026-03 起官方删掉本地暴露抽卡链接的地方。
→ **结论：PC 读日志拿 token 的路子在国服基本失效，不能作为桌面版主路径。**

## 2. 明日方舟 PC 版
- 有官方 PC 端：2026-02-10 起「技术性开放测试（不限量不删档）」，鹰角启动器下载，鹰角通行证/bilibili 登录，数据与移动端互通（确认，news/0717、news/7388）。约 30GB，Win10/11 64 位。
- 寻访记录查询在**官网用户中心**（ak.hypergryph.com/user），不是本地文件。PC 客户端是否内置寻访 WebView 及是否落 token 到日志：**未找到资料，推测没有现成的本地文件可读**（没有任何明方工具读 PC 日志，全部走账号 token）。
- 现有明方工具全部用账号 token：arkntools/arknights-gacha-export、AceDroidX/arknights-gacha-export、RWoxiN/ArknightsDataAnalysis、Gordenghost/arklog（后者支持手机号+验证码六步登录链，国服实测跑通）。account/info/hg 的 token「官服有效期非常短，B 服非常长」（源码确认，arkntools README）。
→ **明方桌面版只能做“内置浏览器登录 / 粘贴账号 token”，没有本地文件捷径。**

## 3. 森空岛（Skland）
- 森空岛**自身没有寻访记录接口**（docs/research.md 已记）。但它和明方/终末地共用鹰角通行证，可借它登录拿账号 token。
- 两类凭证（ProbiusOfficial/Skland_API、arklog 源码确认）：
  - 账号 token：grant(appCode=be36d44aa36bfb5b,type1,返回 data.token) → 走 ArkRecord 链拿寻访。这是能用的。
  - cred：grant(appCode=4ca99fa6b56cc2ba,type0,返回 data.code) → generate_cred_by_code 换 cred，只能查森空岛玩家信息/干员/签到，**换不到寻访**。arklog 专门检测“返回 code 而非 token”并报错。
- 森空岛开放接口对 ArkRecord 的用处：干员持有/练度、玩家基础信息（可做“已有干员”标注，但与寻访统计无关）。
- 登录认证：手机验证码 / 扫码（gen_scan/login→scan_status→token_by_scan_code，源码确认 nonebot-plugin-skland/api/login.py）。
- 风险：generate_cred_by_code 自 2024-09 起需数美(ShuMei)设备指纹 dId，否则“设备信息无效”；时钟偏差 >30s 被拒(10003)；海外 IP 可能触发风控(1903)（转述 + ArkMowers PR#938 2026-09-04）。**但 ArkRecord 只要账号 token，不碰 cred/签名，可完全避开数美这套。**

## 4. 鹰角通行证登录流程（实测 + 读官方前端 JS）
- 登录页 user.hypergryph.com/login，SPA，加载 web.hycdn.cn/user-center/index.*.js → hg_web_sdk@3.0.3 → hg-account-web-sdk@3.5.0。
- 登录方式（实测，读 uc.js）：手机验证码 token_by_phone_code、账号密码 token_by_phone_password、扫码 gen_scan/login+scan_status+token_by_scan_code（扫码用鹰角 App/森空岛扫，不是网页）。
- 人机验证：有。SDK 带状态码 REQUIRE_CAPTCHA=1，调 `window.initGeetest4({captchaId,riskType,product:"bind"})`，请求头 `X-Captcha-Version: 4.0` → **极验 Geetest v4**（实测）。不是每次都弹，由 REQUIRE_CAPTCHA 触发。
- 设备指纹：请求头 X-DeviceId（localStorage `hg_sdk_device_id`，随机 uuid）、X-DeviceType:7、X-OSVer。有“新设备登录身份验证”开关（开启后新设备要验证）。
- token 存哪：登录成功后账号 token 由 SDK 的 User.saveToken() 托管，不是裸写某个固定 cookie/localStorage 键（实测）。account/info/hg 的作用是**把当前登录态（服务端 HttpOnly cookie，实测响应带 `set-cookie: aliyungf_tc=…HttpOnly`，credentials 模式）回显成明文 token** 供复制。SDK 还支持 URL 参数 `?hg_token=` 跨页传递登录态。
- 有效期：官服短、B 服长（源码确认，具体时长无权威值）；短 token 约 1~3 月（RoLingG-core 转述）。刷新：重新登录官网再复制。
- **关键 CORS 实测（2026-10-18）**：web-api.hypergryph.com/account/info/hg 用的是**白名单式 CORS**，`Access-Control-Allow-Credentials: true`，ACAO 精确回显来源**仅限鹰角自己的域名**（ak./endfield./user.hypergryph.com、www.skland.com），对 ark.kaltsit.dev 等外部来源不回 ACAO。account/info/hg/check 的预检 204 允许 GET/POST/DELETE + content-type。
- **桌面应用内置 Chromium 登录官方页、登录后请求 account/info/hg 拿 token：可行**（bhaoo、RoLingG 都这么做）。坑：
  1. account/info/hg 靠**登录后服务端 cookie**（HttpOnly，JS 读不到），所以内置 WebView 必须**在同一个带 cookie 的上下文里**发请求（页面内注入 fetch(credentials:'include')，或读 WebView cookie jar），bhaoo 的做法正是在页面内轮询该接口拿 data.content。
  2. 外部进程/桌面 app 直接 CORS 请求该接口会因白名单失败 → 必须在 WebView 内、以官方域名为来源发，或走原生 HTTP 不受 CORS 限制。
  3. 登录可能弹 Geetest v4；内置真实官方页能正常过，自己仿接口则要处理人机验证。
  4. 新设备验证开关、设备指纹头（X-DeviceId）——用内置官方页+SDK 自动带，不用自己造。
  5. user.hypergryph.com / ak.hypergryph.com / web-api 都**没有设置 CSP / X-Frame-Options**（实测），所以可嵌 iframe/WebView。

## 5. 安全与合规
- **读本地游戏日志/缓存拿凭证 vs 读浏览器 cookie 库**：
  - 终末地日志里的 u8_token 是**明文、在用户自己机器上、游戏自己写的**，读它不碰游戏进程/内存/封包。按性质最接近“读本地文件”。但据 17173 转述，终末地（尤其外服）的这个 token「不随重新登录或时间过期」，比原神 authkey 风险更高——日志一旦泄露等于长期账号钥匙。
  - 读浏览器 cookie 库（如 Chrome 的 Login Data/Cookies）要解 DPAPI；Chrome 127(2024-07)起上了 App-Bound Encryption，只有 Chrome 自身能解，第三方读会更难也更“吵”（转述）。Electron 也有 EnableCookieEncryption fuse。→ 读浏览器 cookie 是典型 infostealer 行为，不要做。
- **鹰角用户协议要点（实测，user.hypergryph.com/protocol/plain，更新 2025-07-25）**：
  - 通行证注册协议 3.1「不得以任何方式将通行证提供给他人使用，包括出售、赠予、转让、出借、出租」；4.1/4.3 妥善保管密码/验证码/令牌。
  - 游戏使用许可协议 6.2(16)「通过非鹰角开发或未经授权的第三方软件、插件、外挂、系统，使用鹰角游戏软件及服务…」属禁止行为；6.2(18)「对…客户端与服务器端的交互数据…复制、修改…挂接运行…包括使用插件、外挂或非经合法授权的第三方工具/服务接入软件和相关系统」；6.1(15) 禁反向工程。6.3 可警告/封停。
  - ⚠️ 读自己的寻访记录、复制自己的 token，协议里没有明确许可条款（gacha-hub ADR0009 也说“nothing found forbids reading one's own records”），但 6.2(16)(18) 对“第三方工具接入”写得很宽，桌面版属灰区。合规上最稳的是**内置官方登录页让用户自己登录、只读自己的数据、token 不出本机**。
- **第三方工具被警告/封号案例**：
  - 终末地上线即发公平运营声明禁外挂/第三方工具，承诺后台监控+举报处罚（扣收益/冻结/封停）（转述，36kr/新浪，2026-01）。外挂主要针对 PC，与抽卡查询不同性质。
  - 没有找到“因用抽卡查询工具被封号”的确证案例；Endfield Tracker 自称“no confirmed bans”（其自述）。
  - **EndfieldRecords 恶意软件事件（2026-02~03，转述 GamingonPhone）**：该站让用户跑 PowerShell/上传游戏日志，脚本被换成含恶意代码版本（回连 rouf.xyz、建计划任务做持久化），有用户电脑被黑。→ 「让用户跑第三方脚本/上传日志」模式本身就是高风险，ArkRecord 不应采用。

## 6. 结论建议
### 桌面版（Electron+Python）
- **终末地**：首选=**内置 Chromium 窗口登录鹰角官网，页面内抓账号 token**（像 bhaoo）。token 不落盘、只发 *.hypergryph.com。备选=手动粘贴 account/info/hg 的 data.content。**不要**把读 HGWebview.log 当主路径（1.1 后国服失效），顶多作为“已登录游戏时”的降级尝试并明确提示可能失效。
- **明日方舟**：同样首选内置官网登录抓 token，备选手动粘贴。无本地文件捷径。
- 两者 token 获取后走同一条 as grant → binding → u8 链（appCode 都是 be36d44aa36bfb5b，binding_list 的 appCode 分 arknights/endfield）。官服 token 很快过期，要设计“过期即提示重新登录”。
- 安全硬约束：token 只在内存/加密本地存储（参考 Thanatosoul AES+设备指纹、xqf946 只发鹰角域名的闸门）；Electron 建议开 EnableCookieEncryption fuse；绝不让用户跑外部脚本/上传日志。

### 网页版能否借鉴
- **浏览器扩展**：可行且体验好（如 Endfield Overseas Gacha Helper：引导到官网、登录后读 token 传分析站——但那是把 token 交第三方站，ArkRecord 要做成“只在本地/只发同源 Worker”）。扩展能跨域读官方接口、能在官方页上下文里取登录态，比 bookmarklet 强。成本是要分别上架 Chrome/Edge/Firefox 商店。
- **bookmarklet 一键复制**：在 web-api.hypergryph.com/account/info/hg 这个**纯 JSON 页面**上，CSP 实测为空（该接口无 CSP 头），`javascript:` 书签理论上能跑、能 `fetch(credentials:'include')` 读 data.content 并复制到剪贴板。但：① 该页是 JSON 不是 HTML，书签在纯文本响应页上行为不稳；② 更该在 user/ak 官网页面跑再 fetch 接口（同源、带 cookie），这些页也没 CSP（实测），可行性较高；③ Geetest/登录态要用户先登录好。整体可做“辅助复制”，但不如扩展稳。
- 仍受 account/info/hg 的 CORS 白名单限制：扩展/bookmarklet 必须在鹰角官方域名的上下文里发请求，不能从 ark.kaltsit.dev 直接 fetch。
