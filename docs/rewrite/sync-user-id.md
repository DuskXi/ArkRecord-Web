# 同步识别码（2026-10-19）

维护者的要求（原话）：“加入同步随机识别码，开通同步的时候识别码就生成，后续存在浏览器里面无论开关都不删除，开了同步就往同步里面传，跨账号共享识别码，作为真独立用户识别，只有冲突的时候询问一下用户。”

维护者另外定的两条：

- 网页版的统计也上报识别码，但仍然要用户在统计同意里选“全部接受”；桌面版默认开启（和桌面版其他统计一样）。
- 冲突时用户选“是同一个人”，保留**先生成的**那个识别码。

维护者确认后已实现（2026-10-19），先在测试站上线。下面是实现后的设计；代码位置见最后一节。

## 识别码是什么

- 128 位随机数（`crypto.getRandomValues`），写成 32 位十六进制，附带生成时间（毫秒）：`{ id, createdAt }`。
- 不包含、也推不出任何账号、设备或个人信息。
- 一台设备（一个浏览器，或者桌面版）只有一个，同一个人的所有账号共用。

## 存在哪里，什么时候删

- 存在本地 IndexedDB 的 `kv` 表（`sync-user`）。网页版和桌面版都是这样存的；桌面版的识别码和设备统计用的随机设备编号是两回事，互不关联。
- **任何开关都不删它**：关闭云同步、删除云端数据、忘记密码、关闭统计、删除账号，都不删。
- 只有用户清除浏览器数据（或者删掉桌面版的数据目录）时才会没有。之后再同步时，会从云端把它找回来（见下面“生成和沿用”）。

## 随同步数据上传

- 放在每个账号云端数据的头部：`user = { id, createdAt, merged? }`（和账号信息 `account` 并列）。云同步是端到端加密的，**服务器看不到识别码**。
- 合并规则：两份数据的 `user` 不同时，保留 `createdAt` 更早的；时间相同时取 `id` 字典序更小的。另一方的 `id` 和双方的 `merged` 并进 `merged`（排好序、最多 64 个），记下“这些识别码是同一个人”，其他设备看到后就不会再问。规则和顺序无关，满足现有合并的幂等、交换、结合要求（cloud-sync.md 10.1）。
- **格式版本**：带 `user` 的数据写成**版本 3**。按现有的版本门槛规则，没有更新的旧网页读到版本 3，只读不写，并提示刷新网页。
  - 后果：上线以后，开着云同步的账号会陆续写成版本 3。还开着旧网页的设备，刷新一次就恢复正常，数据不会丢。
  - 规范唯一：没有 `user` 时照旧写成版本 1 或 2。
  - 网站还没更新时不上传：网页和 Worker 一起部署，`/api/cloud/v1/info` 的 `dataFormat` 是这个网站的网页能读的最高版本（`shared/cloud-protocol.ts` 的 `DATA_FORMAT_VERSION`）。客户端上传前先看它，没有这一项或小于 3 时，上传的数据去掉 `user`（识别码留在本机和本地账号里），网站更新后下次同步自动补传。用在桌面版同步到还没更新的正式站时，那边的网页不会因此读不了。

## 生成和沿用

开通或同步某个账号 A 时，设本机识别码为 D（可能没有），A 在云端的识别码为 C（可能没有）：

| D | C | 做什么 |
|---|---|---|
| 没有 | 没有 | 生成新的 D，A 的数据带上 D |
| 有 | 没有 | A 的数据带上 D |
| 没有 | 有 | 本机沿用 C（D = C），不生成新的 |
| 有 | 有，是同一个人（相同，或者一方的 `merged` 里有另一方） | 两边合并成同一个 |
| 有 | 有，不同 | **冲突，询问用户**（见下），两边都先不改 |

对账发生在开通时，以及每次云同步下载合并之后、上传之前。

## 冲突时询问

弹窗只在冲突时出现，云同步进行中不弹（回答“是同一个人”“不是”后不再问，记在本地）：

> 这个账号的云同步数据里记的是另一个用户识别码。可能是你在别的设备上用过，也可能是别人的账号。是同一个人吗？

- **是同一个人**：保留先生成的那个（`createdAt` 更早的）。本机和本机所有开着同步的账号都改用它，下次同步时随数据上传；其他设备同步到后按合并规则自动改用它，不会再问。
- **不是**（比如借用别人的账号、几个人共用一台电脑）：本机识别码不变；这个账号保留它在云端的识别码，本机以后不会把自己的识别码写进这个账号。
- **以后再说**：这次不改任何东西，下次同步时再问。

## 用于统计

- 统计“独立用户数”：上报识别码加前缀后的 SHA-256，服务器再用 `STATS_UID_SALT` 做 HMAC 才保存（和桌面版的 UID 统计相同）。识别码是 128 位随机数，本身就无法反查；加盐是为了和其他计数统一处理。
- 单独一次请求、每天最多一次，和设备、UID 的上报互不关联。
- 网页版：只在“全部接受”之后上报，由网页直接上报（新增同源接口）。桌面版：交给 Python 后端，默认开启，“关于”页可关闭。
- 只有开通过云同步的设备才有识别码，所以这个数是“用过云同步的独立用户数”。
- 网页版“关于”页、统计同意弹窗、SECURITY.md 都已改成如实说明。

## 代码位置

1. `src/lib/cloud/codec.ts`：头部可选的 `user`，格式版本 3，规范唯一（`checkSyncUser`）。
2. `src/lib/cloud/dataset.ts`：下载时并入本地账号（`mergeAccountUser`），上传时带上；`user` 有自己的记录哈希（`u`），只改了识别码也会上传。
3. `src/lib/sync-user.ts`：本机识别码（kv 表 `sync-user`）、对账（`reconcile`）、冲突记录（kv 表 `sync-user-conflicts`）、回答冲突（`resolveConflict`）；`engine.ts` 在开通和每次同步时调用 `reconcileAccountUser`。
4. `src/components/cloud/SyncUserConflictDialog.vue`：冲突弹窗（网页版和桌面版共用）。
5. 统计：`worker/desktop-stats.ts` 的计数种类 `user`、`user:web`、`user:desktop`（接口 `POST /api/stats/user` 和 `POST /api/stats/desktop/user`）；网页版 `src/lib/sync-user-stats.ts`；桌面版 `desktop/backend/arkrecord_backend/stats.py`（`stats.report` 的 `user`）。
6. 测试：`src/lib/sync-user.test.ts`（规则和本地存储）、`src/lib/cloud/engine.test.ts`（四台设备的完整流程）、`src/lib/cloud/codec.test.ts`、`worker/desktop-stats.test.ts`、`desktop/backend/tests/test_stats.py`。网页版和 Python 的哈希用同一个固定值互相核对。
