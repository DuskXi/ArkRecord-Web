# 森空岛截图识别（实验）

目标：用户上传森空岛的干员列表截图，在浏览器里识别出每个干员（名字、星级、终末地的潜能），
补全图鉴里只靠寻访记录统计不到的部分。全部在前端完成，截图不上传。

状态：**实验中**，代码在 `src/lib/screenshot/`，还没有接入界面。

## 做法

只依赖 RGBA 像素数组（浏览器里来自 canvas 的 `ImageData`），不需要 OpenCV。

| 步骤 | 代码 | 做法 |
|---|---|---|
| 找卡片 | `grid.ts` | 左边缘估计页面背景色 → 按列统计前景比例得到每一列 → 行距用自相关求出 → 长截图是拼接的，行距有几个像素出入，每一行在预计位置附近和“平均卡片”对齐 → 去掉被截断的卡片 |
| 终末地星级 | `endfield.ts` | 卡片最下面颜色条的色相：橙 ≈ 26° 为 6★，金 ≈ 48° 为 5★，紫 ≈ 263° 为 4★ |
| 终末地潜能 | `pentagram.ts`、`endfield.ts` | 见下一节 |
| 明日方舟星级 | `arknights.ts` | 卡片顶部找黄色星星那一行；星星左对齐、间距固定（卡片宽度的 0.0817），以第一颗星为参照逐个星位判断；再用这一排的长度核对 |
| 名字区域 | `text.ts` | Otsu 自动门槛二值化，去掉贯穿整行的线条和装饰（明日方舟名字左边的斜条），裁到文字范围，白底黑字 |
| 名字 | `identify.ts`（`names.ts`、`visual.ts`） | 两个信号：OCR 结果按编辑距离匹配已知名字（长名字很准）；把候选名字用系统字体画出来比字形（生僻的单字名也分得开）。两者一致最可靠；星级只作为偏好；一张截图里每个名字只分配一次，先分配把握大的 |

## 终末地的五角星：潜能

卡片左下角的五角星由 5 笔组成，每一笔是白色、黄色，或者没有画出来。在 30 张卡片上读出来的规律：

| 读到的笔画（按解锁顺序 0→4→3→2→1） | 卡片 | 推断 |
|---|---|---|
| 只有 0 是黄色 | 洁尔佩塔、诀、弭弗、汤汤、梨诺 | 潜能 0 |
| 0 白，4 黄 | 莱万汀、骏卫、别礼、提弗洛斯 | 潜能 1 |
| 0、4 白，3 黄 | 余烬、黎风 | 潜能 2 |
| 0、4、3 白，2 黄 | 庄方宜、祀 | 潜能 3 |
| 0、4、3、2 白，1 黄 | 管理员 | 潜能 4 |
| 5 笔全白 | 全部 4★、5★，以及艾尔黛拉 | 满潜能 5 |

即：白色是已解锁的潜能，黄色是下一级，按固定顺序解锁，全白为满潜能。**这是从截图推断的，需要和游戏内的潜能对照确认。**

识别时只依赖黄色那一笔的位置：黄色饱和度高，在任何背景上都好认；白色笔画在浅色立绘上会看不清，只用来核对（30 张卡片里读到的白色笔画全部符合上表，没有一张矛盾）。

|---|---|---|
| 找到的卡片 | 30 / 30 | 56 / 56 |
| 星级 | 30 / 30 | 56 / 56（都是 6★） |
| 潜能 | 30 / 30，没有标为请确认的 | — |
| 名字：OCR 原样完全正确 | 23 / 30 | 约 46 / 56 |

OCR 认不出的都是生僻的单字名：“黍”认成“了”，“锏”认成“铀”。按字形比较时它们和正确的候选最像，而且领先第二名很多，所以能纠正。只靠字形、不用 OCR，在 147 个 6★ 名字里也能挑对 54 / 56（字体用的是系统里的文泉驿正黑，和森空岛的字体不同）。

## 鲁棒性测试

把两张截图做各种变形，再和原图上的结果比对（“标为请确认”：结果附带 low，界面上应该请用户核对；“没标出的错误”：错了但标为 high）。

终末地：

| 变形 | 卡片 | 星级 | 潜能 | 名字 | 潜能标为请确认 | 没标出的错误 |
|---|---|---|---|---|---|---|
| 原图 | 30/30 | 30/30 | 30/30 | 29/30 | 0 | 0 |
| 缩小到 0.75 | 30/30 | 30/30 | 30/30 | 29/30 | 1 | 0 |
| 缩小到 0.5（卡片 64 像素） | 30/30 | 28/30 | 26/30 | 21/30 | 30（太小，全部请确认） | 0 |
| 放大到 1080 / 1440 宽 | 30/30 | 30/30 | 30/30 | 29/30 | 0–1 | 0 |
| JPEG 质量 40 / 20 | 30/30 | 30/30 | 27/30 | 27–29/30 | 3–6 | 0 |
| 截掉顶部 / 只留中间 | 26/26、12/12 | 全对 | 全对 | 24/26、12/12 | 0 | 0 |
| 变暗 0.8 / 降低饱和度 0.7 / gamma 1.8 | 30/30 | 30/30 | 30/30 | 28–29/30 | 0 | 0 |
| 变亮 1.15（页面背景变成和名字栏一样白） | 29/30 | 23/29 | 23/29 | 22/29 | 6 | 0 |

明日方舟（星级，逐个星位判断；卡片只有 56 像素宽，按规则全部标为请确认）：原图 56/56，缩小 0.75 56/56、0.5 53/56，JPEG 质量 40 55/56、20 43/56，变暗、变亮、降低饱和度、gamma 都是 56/56。

做到这些靠的是：
- 颜色用相对的分数，而不是固定门槛：黄色那一笔只要“明显比其他四笔都黄”，白色笔画只要“比一侧背景亮”；
- 压缩把黄色洗掉时，改用“亮的笔画正好是解锁顺序的前几笔”推断，并标为请确认；
- 每张卡片用名字栏上沿重新对齐（长截图拼接造成的行距误差）；找不到时扩大范围；
- 卡片宽度低于 90 像素时，潜能和星级一律标为请确认。

还没覆盖的：明日方舟 5★ 以下（逐个星位判断时，立绘的黄色紧挨着最后一颗星可能多数一颗，会和长度核对不一致而标为请确认）、深色主题、横屏 / 平板的列数、截图里混入弹窗或滚动条。

## OCR 的选择

- Tesseract.js：核心 WASM 约 3 MB，简体中文模型 `chi_sim`（4.0.0_best_int）约 1.7 MB（gzip）。每张名字图约 25–40 ms。只在用户打开识别功能时加载。
- 名字是已知集合，OCR 认错一两个字也能纠正，所以不需要更重的模型。如果原图上的准确率仍然不够，再考虑 PaddleOCR（onnxruntime-web）。
